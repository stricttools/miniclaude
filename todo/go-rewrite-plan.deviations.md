# Deviations from the Go rewrite plan

- The `go.sum` holds the h1 and `go.mod` lines of the modules `go.mod` lists, copied from dirstat's `go.sum` (and go-toml/v2 from a sibling project's), and nothing for the modules further down the graph (strictcli's jsonschema and x/text, x/term's x/sys v0.46.0); dirstat builds with the same partial set for strictcli. Any line the first compile asks for is added then, never invented. Decided by the build.
- Display widths come from a fixed go-runewidth condition (East Asian ambiguous characters one column, emoji and wide characters two), not from the locale, so rendering does not depend on the environment. Combining and control characters count zero columns where the Python counted one. Decided by the build.
- Whitespace trimming in the renderer and dialogs follows Python's `str.isspace` (Unicode white space plus U+001C to U+001F), and line splitting in the permission description follows `str.splitlines`, so the rules match the Python. Decided by the build.
- The renderer returns an ordered list of segments (prose text or a table) from each feed call instead of a string plus a table callback. The Python fired the table callback before printing prose emitted earlier in the same call, so a table could appear above the paragraph that preceded it, depending on how the stream was split; ordered segments keep the output identical however the stream is split. Decided by the build.
- `render.Table.Render(width)` returns one string per terminal row without newlines, so the method value serves as the `func(width int) []string` the output view takes for table blocks. Decided by the build.
- Tool input reaches the formatters as `map[string]any`, which keeps no key order: the summary of an unrecognized tool lists its keys sorted, and an MCP tool's summary shows the first key in sorted order (the Python used the first key as sent). Non-string values are shown as Python's `str()` showed them (True, False, None, quoted strings inside lists and objects); numbers that are whole are shown as integers, since JSON integers decode to float64. Decided by the build.
- `toolline.FormatToolResult` takes the result content as `json.RawMessage` and a boolean for subagent activity (the Python took the parent tool-use ID); it returns an error when the content is not valid JSON. The tool name the Python accepted and never used is dropped. Decided by the build.
- The Write permission description counts the content's UTF-8 bytes, as its "bytes" label says; the Python counted characters. Decided by the build.
- Compact JSON in the permission description and suggestion labels is written by encoding/json with HTML escaping off; it still escapes U+2028 and U+2029, and whole floats print without ".0", where Python's json.dumps did neither. Decided by the build.
- The dialogs package exposes pure pieces for the flow the controller writes: `PermissionChoices`, `Decide(req, choice, message)` returning a `Decision{Allow, UpdatedInput, UpdatedPermissions, Message}`, `PermissionDismissed`, `Questions(input)` (an error for a malformed questions array, where the Python crashed), `SingleChoiceMenu`, `NumberedOptions`, `ParseMultiSelect` (ASCII digits only), `SingleChoiceAnswer`, `MultiSelectAnswer`, `QuestionAnswers`, `QuestionDismissed`, `DialogNotice`, and the prompt texts as constants. Decided by the build.
- The format helpers live in `internal/usageformat` and take local structs (`ModelUsage`, `Result`, `ContextUsage`) the controller fills from claudestream's types. When the session's model has no context-window entry, `ContextPercent` uses the first entry in model-name order that has one (a decoded map keeps no order; the Python used the first entry as sent). Rounding is half to even, as Python's `round`. Decided by the build.
- Value formatting shared by toolline and dialogs (display text of decoded JSON values, truthiness, compact JSON, Python whitespace and line splitting) lives in `internal/displaytext` rather than being repeated in each package. Decided by the build.
