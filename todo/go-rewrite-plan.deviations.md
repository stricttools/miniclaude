# Deviations from the Go rewrite plan

- The `go.sum` holds the h1 and `go.mod` lines of the modules `go.mod` lists, copied from dirstat's `go.sum` (and go-toml/v2 from a sibling project's), and nothing for the modules further down the graph (strictcli's jsonschema and x/text, x/term's x/sys v0.46.0); dirstat builds with the same partial set for strictcli. Any line the first compile asks for is added then, never invented. Decided by the build.
- Display widths come from a fixed go-runewidth condition (East Asian ambiguous characters one column, emoji and wide characters two), not from the locale, so rendering does not depend on the environment. Combining and control characters count zero columns where the Python counted one. Decided by the build.
- Whitespace trimming in the renderer and dialogs follows Python's `str.isspace` (Unicode white space plus U+001C to U+001F), and line splitting in the permission description follows `str.splitlines`, so the rules match the Python. Decided by the build.
- The renderer returns an ordered list of segments (prose text or a table) from each feed call instead of a string plus a table callback. The Python fired the table callback before printing prose emitted earlier in the same call, so a table could appear above the paragraph that preceded it, depending on how the stream was split; ordered segments keep the output identical however the stream is split. Decided by the build.
- `render.Table.Render(width)` returns one string per terminal row without newlines, so the method value serves as the `func(width int) []string` the output view takes for table blocks. Decided by the build.
- Tool input reaches the formatters as `map[string]any`, which keeps no key order: the summary of an unrecognized tool lists its keys sorted, and an MCP tool's summary shows the first key in sorted order (the Python used the first key as sent). Non-string values are shown as Python's `str()` showed them (True, False, None, quoted strings inside lists and objects); numbers that are whole are shown as integers, since JSON integers decode to float64. Decided by the build.
- `toolline.FormatToolResult` takes the result content as `json.RawMessage` and a boolean for subagent activity (the Python took the parent tool-use ID); it returns an error when the content is not valid JSON. The tool name the Python accepted and never used is dropped. Decided by the build.
- The Write permission description counts the content's UTF-8 bytes, as its "bytes" label says; the Python counted characters. Decided by the build.
- Compact JSON in the permission description and suggestion labels is written by encoding/json with HTML escaping off; it still escapes U+2028 and U+2029, and whole floats print without ".0", where Python's json.dumps did neither. Decided by the build.
- The dialogs package exposes pure pieces for the flow the controller writes: `PermissionChoices`, `Decide(req, choice, message)` returning a `Decision{Allow, UpdatedInput, UpdatedPermissions, Message}`, `PermissionDismissed`, `Questions(input)` (an error for a malformed questions array, where the Python crashed), `SingleChoiceMenu`, `NumberedOptions`, `ParseMultiSelect` (ASCII digits only), `SingleChoiceAnswer`, `MultiSelectAnswer`, `QuestionAnswers`, `QuestionDismissed`, `DialogNotice`, and the prompt texts as constants. Decided by the build.
- The format helpers live in `internal/usageformat` and take local structs (`ModelUsage`, `Result`, `ContextUsage`) the controller fills from claudestream's types. When the session's model has no context-window entry, `ContextPercent` uses the first entry in model-name order that has one (a decoded map keeps no order; the Python used the first entry as sent). Rounding is half to even, as Python's `round`. Decided by the build.
- Value formatting shared by toolline and dialogs (display text of decoded JSON values, truthiness, compact JSON, Python whitespace and line splitting) lives in `internal/displaytext` rather than being repeated in each package. Decided by the build.
- The terminal setup also turns autowrap off (`?7l`, restored with `?7h`) and each draw is wrapped in synchronized-output markers (`?2026`), so a row whose measured width disagrees with the terminal's is clipped instead of shifting every row below it, and terminals that support it draw a frame at once. The cursor is hidden while a frame is drawn and shown at the editor's cursor afterwards, hidden while a modal holds the box. Changed rows are cleared with `CSI 2K` before they are written, since erasing to the end of the line after a full-width row erases its last cell. Decided by the build.
- `term.Guard`, deferred first in a goroutine, restores the terminal on a panic, writes the panic's stack to standard error, and panics again with the same value; every goroutine that can panic while the terminal is open needs its own `defer t.Guard()`. Resize notifications carry no size: a pending notification absorbs later SIGWINCHs and the controller reads the size with `Size`. Decided by the build.
- The key decoder treats LF as Enter (prompt_toolkit maps Ctrl+J to Enter), Backspace as 0x7f or 0x08, ESC followed by anything but `[`, `O`, or CR as Escape and then that key (prompt_toolkit's Alt+key without a binding behaves so), ignores arrow and Home/End modifier parameters, ignores Tab, other control bytes, C1 characters, unknown sequences, and every mouse report except wheel presses (buttons 64 and 65 with the Shift, Alt, and Ctrl bits masked off). An unfinished bracketed paste waits for its end marker with no timeout; its text is delivered verbatim, invalid UTF-8 replaced with U+FFFD, and the editor turns CRLF and CR into LF as prompt_toolkit did. Decided by the build.
- Output scrolls by wrapped rows, not by logical lines as prompt_toolkit's window did, so one wheel move is one screen row, and the view never scrolls past the last row. While the view is scroll-locked, a width change keeps the logical line at the top of the view at the top. Decided by the build.
- Output text is held as complete lines plus the open line after the last newline; only new lines are wrapped on each draw, and the open line is re-wrapped every draw. Adding a table ends the open line first, so a table always starts on its own row, and a table's rows start with no SGR attributes and do not change the attributes carried across prose lines (in the Python, attributes carried through the concatenated text). Decided by the build.
- Control characters in output and input are drawn in caret notation (`^I` for a tab), as prompt_toolkit draws them, two cells wide; C1 control characters are drawn as `?`. A rune wider than the whole width gets a row of its own. Grapheme clusters are not joined: each rune is measured on its own, so emoji ZWJ sequences may be measured wider than they draw (autowrap being off keeps that a clipping problem). Decided by the build.
- The boundary hints expose their expiry (`HintExpiry`) so the controller can redraw when a hint should disappear, in place of the Python's scheduled redraw 0.42 s after the flash. Decided by the build.
- The input editor submits nothing for empty or whitespace-only text, which it clears, and does not record it in the history (prompt_toolkit recorded whitespace-only text). A submitted line repeating the latest history entry is not recorded again, as prompt_toolkit did; `Submit` reports whether the line is a new entry so the caller appends it to the history file. Up and Down move between lines of multiline text and recall history only from the first or last line; edits to a recalled entry last until the next submit or clear, as prompt_toolkit's working lines did. Up and Down keep the column by runes, without prompt_toolkit's sticky preferred column. Decided by the build.
- The suggestion follows prompt_toolkit's rules: it is computed after text is inserted from the text's last line (not blank), searching history entries newest first and each entry's lines last first, is cleared by any other change of the text, is drawn in gray (#666666) only while the cursor is at the end, and is accepted by Right or Ctrl+E there. Decided by the build.
- The history file must end every line with a newline and hold one object with only the `text` field per line; anything else is an error naming the line. A missing file holds no entries. `XDG_STATE_HOME` set to a relative path is refused with an error rather than ignored. The file and its directory are created with modes 0600 and 0700. Decided by the build.
- The prompt_toolkit history parser lives in `internal/history` (`ParsePromptToolkit`), so the import command only reads the source file, parses it, serializes with `history.Marshal`, and writes through the effects handle. It differs from prompt_toolkit in one place: a last `+` line without a trailing newline keeps its last character, which prompt_toolkit's reader cut off. Decided by the build.
- When the frame is taller than the screen, the screen cuts rows from the top, so the status rows and the box stay anchored to the bottom; there is no "window too small" message. The box shows whatever lines it is given (the editor caps itself at ten rows; a modal is not capped). Decided by the build.
- The session interface's `SetModel` takes the model as a string (the `/model` command always names one); the adapter passes its address to claudestream, so resetting to Claude Code's default model is not offered. `Interrupt` returns the still-queued messages as claudestream does, and `GetContextUsage` returns `claudestream.ContextUsage`; events are claudestream's own types. Decided by the build.
- `session.Options` carries the repl flags and the session choice as a `claudestream.SessionResolution` value (`NewSession{}`, `ResumeSession{ID}`, or `ContinueLastSession{}`, never forked); `session.Config` sets `InterceptPermissions` and leaves `SupportedDialogs` nil, as the Python set no dialog list, so the stream options stay claudestream's defaults. `session.Start` returns the adapter; `ModelName` and `PermissionMode` are claudestream's `Model` and `PermissionMode`, empty until Claude Code reports them. Decided by the build.
- The mock refuses as a claudestream session does: `Send` while a turn is open (`ErrTurnActive`), after a turn whose reading was cancelled through its context (`ErrSessionUnusable`), and every call after `Close` (`ErrSessionClosed`); in live mode an answer to a request the turn is not waiting on, or of the other type, wraps `ErrUnknownRequest`. The scripted mode accepts every answer and records it. Decided by the build.
- The live mock's turns run in a goroutine that hands events over an unbuffered channel, so the stream's pauses happen while the consumer reads; `Close` and a cancelled `Next` stop it. The text stream splits by characters (runes), not bytes. The first turn's `SystemInit` reports the session's current model and mode rather than fixed values. Seeds are `uint64`, and the two generators are PCG seeded with the seed and with the seed plus 0x5A17. Decided by the build.
- The mock's `dialogs` command also opens an unsupported dialog (a `UserDialogRequest` named `mock_dialog`) after the permission prompt and the AskUserQuestion, so the dialog notice and `RespondDialogCancelled` are exercised; the Python mock never sent one. Its permission request carries a suggestion with `type`, `behavior`, and `destination` besides the rules, as Claude Code sends them. Decided by the build.
- The howmuchleft runner looks the program up on PATH before every run, so installing it mid-session takes effect at the next run. When it is missing, the status rows are the Python's three "howmuchleft not installed" lines; any other failure (a lookup error, a non-zero exit, no answer within 0.5 s, empty output) is one red "howmuchleft: <reason>" row, with the first stderr line when there is one. Entering or leaving a turn starts the next run at once instead of waiting out the old interval, and the results channel holds only the latest result. Whole-number percentages are encoded without ".0" (encoding/json), which howmuchleft reads the same. Decided by the build.
- Slash commands typed while a turn or a slash command's session call is in progress are queued with the prompts and run in order, as the Python's single queue ran them; the "queued: …" notice shows while either is in progress. A failing `/model`, `/mode`, or `/context` call is shown as a red "error: …" line and the REPL goes on (in the Python the exception ended the REPL). `/model` and `/mode` without an argument show the `--model` and `--permission-mode` values until the session reports its own. Decided by the build.
- An event that cannot be shown (tool result content that is not JSON, a permission request whose description cannot be built, an AskUserQuestion input whose questions are malformed) is reported as a red line and the turn goes on being read, since an unread turn blocks every later one; an unreadable request is denied with "miniclaude could not show this request: <reason>" so Claude Code does not wait on it. The Python ended the turn with the exception and left the request unanswered. Decided by the build.
- An interrupt that fails for a reason other than the 30 s limit is shown as a red line (the Python swallowed it). Past the limit the turn's reading is cancelled (claudestream then refuses further turns) and the controller refuses every later prompt with a red line telling the user to leave with /quit or Ctrl+D; slash commands still run. Decided by the build.
- Modals: a menu shows its heading row (none for a single-choice question, as the Python passed no message) and one numbered row per choice, the highlighted one marked "❯ "; Up and Down move the highlight, the digits 1 to 9 move it to that choice, and Enter picks it. A text question shows its prompt on a row of its own above a one-line editor with no history; Alt+Enter inserts nothing there, and the cursor is shown in it (a menu hides the cursor). The mouse wheel still scrolls the output while a modal is open. Decided by the build.
- History lines are appended by a writer goroutine fed in submit order, so the controller never waits on the file; an append failure is shown as a red line and also returned when the REPL ends, which makes the command exit 1. End of file on the terminal's input ends the REPL as Ctrl+D does; any other read error is a failure. Decided by the build.
- howmuchleft is told the session's model, or the `--model` value before the session reports one; the working directory from the session's SystemInit, or before it the `--cwd` value made absolute (also what Claude Code is started in) or the process's working directory. Decided by the build.
- The REPL handles SIGINT, SIGTERM, and SIGHUP itself through os/signal besides strictcli's cancellation of the command context (which covers SIGINT and SIGTERM only); either ends the loop, restores the terminal, and prints the cost summary, and the command exits with 128 plus the signal number, with an "error: the terminal hung up (SIGHUP)" line for SIGHUP. Decided by the build.
- `repl` keeps `--model` and `--permission-mode` required, as `_cli.py` declared them (claudestream also requires a model), so a claudewheel argv that omits `--model` is refused exactly as the Python refused it. The session selector keeps its three members (`--resume ID`, `--continue-session`, `--new-session`) with `--new-session` as the declared default, stated in the flag's help. `--claude-binary` and `--claudewheel-binary` must be absolute paths; omitted, the program is resolved with claudestream's `ResolveOnPath`. `repl` and `mock` both refuse `--json` and refuse when standard input or output is not a terminal. Decided by the build.
- `mock` parses `--seed` as an unsigned 64-bit integer and picks one at random below 2^31 when it is omitted, as the Python did; the seed is the first output line ("mock seed: N", in dim). Decided by the build.
- `history import` creates the directory and makes it private (Mkdir, then Chmod 0700) before writing the file (the effects handle writes with mode 0644) and then makes the file 0600, all through the effects handle so a dry run records them; it supplies the payload `{from, destination, entries}` and prints "imported N entries from <from> into <destination>" ("would import" under a dry run). An existing destination is refused with exit code 2. Decided by the build.
- The cost summary after the REPL is printed with `ctx.Out`, after the terminal was restored; neither `OwnsStdout` nor `ctx.Document` is used, since both interactive commands refuse `--json`, and no flag is repeatable. Every strictcli option used exists at v0.38.0 under the planned name. Decided by the build.
- The history writer posts an append failure to the controller from a goroutine of its own instead of waiting on the controller itself: the controller can be waiting to send a submitted line on the full history channel, and a writer waiting on the controller would never drain that channel, so the two would wait on each other forever. Decided by the build (review).
- `go.mod` no longer requires `github.com/stricttools/go-toml-edit`, and `go.sum` no longer holds its lines: no package in the build imports it (strictcli v0.38.0 uses `github.com/smm-h/go-toml-edit`), so it was an unused requirement copied from dirstat. Decided by the build (review).
- Submitted history lines no longer go through a buffered channel, which blocked the controller once its backlog filled (a hung filesystem, say), so the earlier entry's premise that the controller waits on a full history channel no longer holds. The controller appends each line to a mutex-protected pending list and leaves a wake-up in a one-slot channel with a non-blocking send; the writer goroutine takes the whole list on each wake-up and writes it in submit order, and the controller never blocks on the history file. Shutdown marks the list closed, and the writer finishes the lines already queued before it delivers its result. An append failure is still posted to the controller from a goroutine of its own, so the writer never waits on the controller. Decided by the build (review).
- `keys.Start` takes a guard function that each of the decoder's two goroutines (the reader and the parser with the Escape timer) defers first, and the REPL passes the terminal's `Guard`; the terminal's own resize-forwarding goroutine defers `Guard` too. A panic in any of them now restores the terminal, where before it left the terminal in raw mode on the alternate screen. Decided by the build (review).
- When the command context's cancellation and a signal are both ready, the REPL takes the signal: on cancellation it first checks its signal channel without blocking, so a SIGINT or SIGTERM ends the REPL with that signal recorded instead of depending on which ready case select picked. The exit code is 128 plus the signal number either way, since strictcli's exit step replaces the handler's code with that whenever its own handling saw SIGINT or SIGTERM; the check makes the REPL's outcome deterministic, and it still covers the narrow window in which strictcli cancels the context before os/signal has delivered the same signal to the REPL's channel only through strictcli's replacement of the exit code. Decided by the build (review).
- `XDG_STATE_HOME` is declared as a strictcli location root (`WithInfraRoot`, default `~/.local/state`, the `history.DefaultStateHome` constant), read in the command handlers with `ctx.InfraValue`, and passed to `history.Path(stateHome)`, so the history package reads no environment variable and the framework-use lint finds no environment read; the root also shows in `--help` and the schema dump. Unset resolves to the default through strictcli; set but empty reaches `history.Path` as an empty value, which it also resolves to the default in the home directory (`os.UserHomeDir`, which the lint does not list); a relative value is still refused. strictcli expands a leading `~` in the variable's value, so `XDG_STATE_HOME=~/state` is now taken as a path in the home directory instead of being refused as relative. Decided by the build (review).

- `repl` keeps `--model` and `--permission-mode` required, as the Python's `_cli.py` had them; claudewheel's Go rewrite always passes both, so its argv without `--model` is not supported. (orchestrator ruling)
- At the first compile the module built and vetted clean; `go mod tidy` (from the module cache, no proxy) dropped the indirect go-toml/v2 requirement (only claudestream's `agent` package imports it, and miniclaude does not) and added the `go.sum` lines of strictcli's own test dependencies, and gofmt rewrote three files' spacing. Decided by the switchover.
- The test suite drives the REPL on a pseudo-terminal (`internal/ptytest`, imported only by tests: the harness and a screen model of the sequences the REPL writes) through the mock session and through a bash stand-in for Claude Code; the test binary runs miniclaude's command line when `MINICLAUDE_TEST_CHILD=1`. The renderer, tool lines, and dialog builders are compared with test data the Python produced (`scripts/python-expectations`, run with the uv tool install's python, recording the Python tests' own calls); the data stays committed when the Python is deleted, and the generator goes with it. A description line holding the tool input as JSON is compared by value, since the Go input keeps no key order. Decided by the switchover.
